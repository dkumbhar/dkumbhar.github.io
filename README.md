# dkumbhar.github.io

Deepak Kumbhar's personal publication on enterprise AI, agentic systems and architecture, served by GitHub Pages at https://dkumbhar.github.io.

The site is plain static HTML. GitHub Pages serves the files in this repository exactly as they are: there is no Jekyll (`.nojekyll` turns it off), no framework, and no build on GitHub's side. One small Python script, run on your own machine, keeps the homepage and index pages in step with the articles.

## Layout

| Path | What it is |
|---|---|
| `index.html` | Homepage. The editorial sections are written by hand. The featured, latest and topic sections and the JSON-LD block sit between `<!-- build:NAME -->` markers and are generated. |
| `articles/<slug>/index.html` | One folder per article. Each article keeps its own inline styles and design. |
| `writing/index.html`, `topics/index.html`, `feed.xml`, `sitemap.xml` | Generated by `scripts/build.py`. Don't edit them by hand. |
| `content/site.json` | Site settings, the topic list, and the article list with each article's category and topic mapping. |
| `assets/site.css` | Shared styles. Every class starts with `dk-`, so the file can't change an article's own design. |
| `scripts/build.py` | Regenerates the files above. Needs Python 3.8 or later and no packages. |
| `scripts/check.py` | Checks links, anchors, headings, alt text, and that no previously published URL has disappeared. |
| `google9b0313b970246087.html` | Google Search Console verification. Keep it. |

## Preview locally

```sh
cd dkumbhar.github.io
python3 scripts/build.py
python3 scripts/check.py
python3 -m http.server 8000
```

Then open http://localhost:8000. Opening the HTML files directly from Finder won't work, because links start at the site root (`/assets/...`).

## Publish

GitHub Pages deploys from the `main` branch root on every commit.

**In the browser:** open https://github.com/dkumbhar/dkumbhar.github.io, choose **Add file → Upload files**, drag in the changed files and folders, and click **Commit changes**. The site updates within a minute or two.

**With git** (if you clone the repository):

```sh
python3 scripts/build.py && python3 scripts/check.py
git add -A
git commit -m "Describe the change"
git push origin main
```

## Add a new article

1. Create `articles/<slug>/index.html`. Copying the existing article is the quickest start. The script reads these values from the page itself, so set them:
   - `<meta name="description" content="...">` becomes the excerpt everywhere.
   - `"datePublished":"YYYY-MM-DD"` in the article's JSON-LD sets the date and the order.
   - The `<h1>` is the article title. Set the card title in `content/site.json`.
   - `<h2 id="...">` headings become linkable sections for the Topics page.
   - Add `<!-- build:continue -->` and `<!-- /build:continue -->` just before `</main>` to get a "Continue reading" block.
   - To share the site's navigation, copy the `<a class="dk-skip">` and `<header class="dk-nav">` block and the `<link rel="stylesheet" href="/assets/site.css">` line from an existing page.
2. Save a 16:9 cover image as `assets/cover-<slug>.webp` (or `.png`/`.jpg`), and a 1200×630 social image for `og:image`.
3. Add the article to `content/site.json` under `articles`, with its `category` (a topic slug) and, if you want, a `topics` map from topic slug to section ids. To change what the homepage leads with, edit the `featured` list.
4. Run `python3 scripts/build.py` and `python3 scripts/check.py`, preview locally, then publish.

Reading time is calculated from the word count at 225 words per minute. Code blocks, diagrams and scripts don't count toward it.

## Rules

- Never rename or delete a published article folder. `scripts/check.py` fails if a URL listed in its `PUBLISHED` table disappears. Add each new article's URL to that table once it's live.
- Topics come from what has actually been published. Only add a topic to `content/site.json` once an article covers it.
